## 为什么需要这个工具

本项目的权威内容分**三层**，改上层不改下层会导致一个隐蔽的 bug：

```
① 事实来源层   规格原文 · 各模块 00-主控智能体.md
② 规则/引擎层  引擎/*.md · 模块 README.md
③ 实体层       ⚠️ 模板/* · 可部署的合并版/总集 · 项目骨架/ 下 _README
```

**问题**：你打开主控看，内容是对的——就以为改完了。但**用户实操时复制的正是第 ③ 层**，拿到的是被取代的旧格式。

**真实案例（2026-09-23）**：把 06 合规主控从「八类风险/六法优化」升级为「十类/八法」并加了未决项联动，也更新了 README 与引擎文件——**但忘了同名模板**。结果用户按模板做合规检查时，拿到的仍是八类/六法。同类问题一次查出 **8 处**。

其中一处尤其严重：`03-分镜导演/README.md` 写了 ID 规则，但**真正粘贴进 GPTs 的两个主工作流文件里一条都没有**——部署出去的 agent 完全不知道有 ID 注册表，整条 ID 机制在 01 环节形同虚设。

**所以：改完请跑一次本工具。**

## 用法

```bash
cd AI漫剧智能体工作流
python 工具/校验.py            # 全量检查
python 工具/校验.py -v         # 额外显示通过的项
python 工具/校验.py --only 机制  # 只跑某一类（引用/机制/禁用/口径/交付包）
python 工具/校验.py --sizes    # 打印可部署文件体积，供部署指南刷表
```

**退出码**：`0` = 全部通过；`1` = 存在失败项（可接入 CI 或提交前钩子）

**依赖**：Python 3.8+，纯标准库，无需安装任何包。

## 七类检查

| # | 检查 | 抓什么 | 触发场景 |
|---|---|---|---|
| 1 | **引用完整性** | 路径式引用指向不存在的文件 | 文件改名/移动后忘了更新引用 |
| 2 | **机制覆盖** | 某机制的关键词没在该出现的文件里出现 | **改主控忘了同步模板** |
| 3 | **禁用前缀** | 已废弃 ID 前缀残留（`SHOT_`/`SCN_`/`SHO_`/`MUS_EP`） | 命名规范改了但全库没 grep 干净 |
| 4 | **口径一致** | 旧口径词残留（如 06 模块仍写"八类""六法"） | 升级数字口径后漏改部分文件 |
| 5 | **交付包字段** | 交付包缺 ID 或未决项字段 | 新增跨模块机制后没推广到所有模块 |
| 6 | **素材完整性** | 规格原文 / 源 skill / 模板被误删 | **误删参考 md**（用户明确要求保留） |
| 7 | **文本完整性** | 全角括号不配对 + 损坏指纹 | **字符级替换事故**（见下） |

### 检查 7 的由来：一次真实的文件损坏事故（2026-09-23）

用 PowerShell 批量替换中文文本时踩了一个隐蔽的坑：

```powershell
# 想替换两个片段，写成嵌套数组
$map = @{ "f.md" = @(@("视觉分镜引擎.md ⭐【视觉分镜】…", "视觉分镜引擎.md ⭐【视觉分镜】…")) }
foreach ($pair in $map["f.md"]) { $c.Replace($pair[0], $pair[1]) }
```

`@(@("a","b"))` 这种**单元素数组会被 PowerShell 展开**，`foreach` 拿到的是**字符串**而不是数组。
于是 `$pair[0]` 取到的是**首字符**，`.Replace()` 退化成**字符级替换**：

| 本意 | 实际执行 | 后果 |
|---|---|---|
| 替换「视觉分镜引擎.md …」 | `Replace('视','觉')` | **全文所有「视」→「觉」**："视觉"→"觉觉"、"视频"→"觉频"、"三视图"→"三觉图" |
| 替换「676 行 / 27.4 KB」 | `Replace('6','7')` 再 `Replace('7','3')` | **全文所有 6 和 7 → 3**，数字全毁 |

**3 个文件被静默损坏，而当时 6 类检查全部通过。**

**检查 7 的设计**：

| 手段 | 说明 |
|---|---|
| **全角括号配平** | 中文文档里 `（`/`）` 逐行配平；字符级替换极易打破（实测一次事故 25 行不配对）。**最可靠的信号** |
| **损坏指纹** | 正常中文不存在的组合：`觉觉` / `觉频` / `三觉图` / `13:9`（应为 16:9） |
| **容忍阈值** | 文件级失衡 ≥2 **且**不配对行 ≥3 才报——避免单行笑脸 `:)` 之类噪声（首版就是被这个假阳性绊了一下） |

> ⚠️ **结论（已写入根 README 质量守则）**：
> **不要用 PowerShell / sed 做中文内容的批量替换**——数组展开、编码、换行符都可能静默损坏文件。
> 改用编辑工具（走 Python），或替换后立刻跑 `python 工具/校验.py`。

### 检查 6 的规则（素材不得误删）

用户明确要求：**参考的 md 很有用，尽量保留、不要删除**。故本检查守护两类资产：

| 类型 | 规则 | 位置 |
|---|---|---|
| **必须存在的具体文件** | 逐项核对存在性 | 见 `校验.py` 的 `REQUIRED_FILES`（规格原文归档、ID/未决项模板、源映射清单、工具自身） |
| **目录最小文件数** | 少于阈值即报警 | 见 `REQUIRED_DIR_MIN`（分镜源 skill ≥10、服化道源 skill ≥22、引擎 ≥8、规格原文 ≥3…） |

> 实现注意：本检查**直接查文件系统**（不依赖 `walk_files` 的扩展名过滤），否则 `.py` 等非 md/yaml 文件会被误判为缺失——这个 bug 在本检查首次运行时就被自己抓到了。

### 检查 1 的豁免规则（避免误报）

以下引用**不算断链**，已内置豁免：

| 类型 | 例 | 为什么不算 |
|---|---|---|
| 项目内部路径 | `00_PROJECT/ID-REGISTRY.md` | 项目中才会有，库内不存在属正常 |
| 源仓库待抓清单 | `角色/四视图大师.md` | INDEX 的用途就是列待抓项 |
| 源 skill 内嵌 references | `references/core-methodology.md` | 是源 skill 自带的参考库章节，不是独立文件 |
| glob 通配 | `引擎/*.md` | 非具体文件引用 |

## 如何新增检查

规则以**声明式表格**写在 `校验.py` 顶部，加检查只需加一条规则，**无需改逻辑**：

### 新增「机制覆盖」规则

```python
MECHANISM_RULES = [
    ...
    {
        "name": "你的机制名",
        "keyword": "必须出现的关键词",
        "must_in": [
            "该机制应出现的每个文件路径",
        ],
    },
]
```

### 新增「禁用前缀」

```python
FORBIDDEN_RULES = [
    ...
    {
        "name": "说明",
        "pattern": r"错误前缀_",
        "should_be": "正确前缀_",
        "exempt_files": ["归档目录/*"],        # 豁免文件（glob）
        "exempt_line": r"不是|已废弃|勿部署",   # 豁免「说明性文字」行
    },
]
```

> **豁免项设计说明**：很多"错误前缀"出现在**警示文本**里（如"分镜是 `SHT_` 不是 `SHOT_`"）。`exempt_line` 就是为了区分「用错」与「提醒不要用错」——没有它会产生大量假阳性，工具就会被人忽略。

## 已发现的「文档数字漂移」问题（附 `--sizes` 的由来）

体积/行数这类**硬编码在文档里的数字**极易过期。本项目实测：

| 位置 | 曾写 | 实际 | 原因 |
|---|---|---|---|
| `快速部署指南.md` | 合并版 77.3 KB | 31.4 KB | 上轮去重后忘了改 |
| 各处 | 调音大师班规格 1824 行 | 2344 行 | **PowerShell `(Get-Content).Count` 计数不准**，需用 Python `count("\n")` 核对 |
| 各处 | Suno 规格 2482 行 | 3038 行 | 同上 |
| `04/README` | 02 引擎约 560 行 / 21.4 KB | 724 行 / 28.8 KB | 估算未实测 |
| `01/_规格原文/README` | 视觉分镜引擎 24.8 KB | 25.5 KB | **文本模式读取 + 编码计数会偏小**（见下） |

### ⚠️ 第二种测量陷阱：换行符

本项目实测：`write_to_file` 在本系统产生 **CRLF** 文件，而用户提供的规格原文是 **LF**。

| 测量方式 | 结果 | 是否正确 |
|---|---|---|
| `os.path.getsize(p)` | 25.5 KB | ✅ 磁盘真实体积 |
| `open(p).read()` → `.encode('utf-8')` 后取长度 | 24.8 KB | ❌ **偏小**（文本模式把 `\r\n` 归一为 `\n`，每行少 1 字节） |

**结论**：
1. **体积一律用 `os.path.getsize`（即 `--sizes` 的口径）**
2. **行数用 `count("\n") + 1`**
3. 混用两种口径会导致"同一文件两个体积"——本项目已踩过一次

## 三、融入新规格的标准流程（已实践 2 次）

用户提供一份新规格（通常 2000-3000 行 / 70-80 节）时，按以下顺序做：

```
① 原文归档
   复制到对应模块的 _规格原文/（不删除、不修改原文件）

② 冗余审计
   python 工具/提取目录.py  →  看有多少节
   通读一遍，列出重复项（本项目实测：输出模板重复 6 处、调整指令 7 处、执行流程 2 处…）

③ 提炼
   写成「引擎文件」（声明式、无冗余、可直接部署）
   原则：保留全部可复用词汇与机制，只删重复表述与冗余指令

④ 保真度验证  ← 关键步骤，不可省
   写脚本对比原文与提炼版的关键词汇清单
   标准：原文命中的关键词，提炼版 0 丢失
   （这一步是「提炼」与「阉割」的分界）

⑤ 建落点索引
   在 _规格原文/README.md 里把每节映射到提炼版章节
   并明确标注「只在原文里的内容」+ 何时该查原文

⑥ 接线（最易漏，见下）
   主控指向新引擎 · 模块 README · INDEX · 根 README · 部署指南 · 总控路由

⑦ 校验
   python 工具/校验.py  →  6 项全过
   另：把新机制加进 MECHANISM_RULES，防止未来漏同步
```

**已有产物对照：**

| 原文 | 节数/行数 | 提炼产物 | 落点索引 |
|---|---|---|---|
| 调音大师班 | 72 节 / 2344 行 | `05-音乐音频/01-声音设计引擎.md`（480 行） | `04/_规格原文/README.md` §四 |
| Suno 歌词大师 | 80 节 / 3038 行 | `05-音乐音频/02-Suno歌词引擎.md`（724 行） | `04/_规格原文/README.md` §三 |
| AI漫剧服化道 V2.0 | 52 节 / 1698 行 | 直接作主控（未提炼，SHA256 逐字节一致） | — |

## 四、改动后的三层同步（第 ⑥ 步的展开）

接线时最容易只改上两层而漏掉实体层：

| 层 | 内容 | 必须同步 |
|---|---|---|
| ① 事实来源层 | 规格原文 · 各模块 `00-主控智能体.md` | — |
| ② 规则层 | `引擎/*.md` · 模块 `README.md` | 指向 ① 的引用 |
| ③ **实体层** | `模板/*` · 可部署合并版/总集 · `项目骨架/` 下 `_README` | ⚠️ **逐个同步** |

**优先检查会被用户直接复制的文件**（模板、合并版），它们比 README 更重要。

## 五、局限（诚实说明）

1. **机制覆盖是"关键词存在性"检查**，不是语义检查。若有人在文件里写"本模块**没有** ID 注册表机制"，关键词存在即通过。**它抓的是"漏改"，不是"改错"。**
2. **口径一致依赖人工维护词表**——新增数字口径时需手动加一条 `STALE_TERMS` 规则。
3. **不能替代实际跑一遍示例**——本项目的经验是「结构完备性不能靠通读文档判断，必须实际跑一个完整示例」（见 `示例演示/01-全流程走通.md`）。本工具只覆盖**机械一致性**，覆盖不了**逻辑可用性**。
