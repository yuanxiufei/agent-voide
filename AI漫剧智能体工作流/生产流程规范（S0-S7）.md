## 一、S0–S7 总表

| 阶段 | 负责模块 | 输入 | 输出 | 落盘位置 | 门禁（怎么算过） |
|---|---|---|---|---|---|
| **S0 建纲** | 01 剧本文本 | 小说 / 创意 | 剧本 · 角色小传 · 大纲三表 · **ID 注册表** · **未决项表** | 项目 `00_PROJECT/` | `python main.py gate script <交付包>` 通过 |

| **S2 出图** | 02 服化道 | S1 的提示词 | 三视图 / 场景六角度 **PNG** | `02_CHARACTERS/` `03_COSTUMES/` `04_PROPS/` `05_ENVIRONMENTS/` | 三视图三张能看出**同一人**；场景六角度**空间一致** |
| **S3 表情 / 动作** | 02 服化道 | S2 的角色图 | `EXP_` / `POS_` 派生资产 | `06_EXPRESSIONS/` `07_POSES/` | 派生 ID 只在**主 ID ≥ DRAFT** 时才建 |

| **S5 视频** | 04 视频生成 | S4 分镜表 | 每镜视频 `VID_SHT_*` | `09_SHOTS/` | 镜间连贯（首尾帧接得上） |
| **S6 音频** | 04 / 05 | 台词 + 情绪线 | `AUD_BGM_*` `AUD_SFX_*` `AUD_VO_*` | 音频目录（04/05 定） | 每条 `AUD_` 已登记 |
| **S7 合规** | 06 合规审核 | 全部产物 + 未决项表 | 一致性报告 + 未决项核查结论 | `10_CONSISTENCY/REPORT_<日期>.md` | **所有 BLOCKING 项 CLOSED** 才可发布 |

> ⚠️ **S7 不是"发现问题的阶段"，是"核对已登记问题"的阶段** ——
> 详见 `01-剧本文本/模板/OPEN-ISSUES.md` §六（那里有明确的措辞要求）。
> ⚠️ **BLOCKING 阻断发布 ≠ 阻断生产**：授权未定时仍可继续出画面，用临时音轨，**让生产与法务并行**。
> 但有一类例外：**改编权类的 BLOCKING（如"原著授权未确认"）建议在该模块投入前先关掉** ——
> 它决定"这片子能不能做"，不是"能不能发"。

## 二、★ 三条机制（本文件新增的核心内容）

### 2.1 增量生产 —— 每集只做本集**新增**

**问题**：不做增量 → 每集都重出全部资产 → ① 成本翻倍 ② **同一空间被重画 = 空间漂移**（比成本更致命）。

**机制**：每集开工前先填一张**物料单**（§三 模板），把资产分成两栏：

| 栏 | 处理 |
|---|---|
| **本集新增** | 才进 S2 生产 |
| **复用** | 直接用已有的；**已 `LOCKED` 的不许重出**。若确实要改 → **升版本号**，不换 ID |

### 2.2 派生不占号

同一实体的**形态变化**一律派生，**不新开 ID**：

| 变化 | 派生形式 | 例 |
|---|---|---|
| 年龄 / 形态 | `_State_X` | `CHR_001_State_9y` |
| 服装状态 | `_Wet` `_Dirty` `_Damaged` | `CST_003_Wet` |
| 道具状态 | `Intact` `Damaged` `Bloody` | `PRP_009_intact` |
| 改版 | `_v<n>` | `CHR_002_v2` |
| 表情 / 镜头视频 | `EXP_` `VID_` | `EXP_CHR001_愤怒` |

> ⚠️ **真需要新号**（新角色/新服装/新道具/新场景）→ **先登记再使用**，号位**永不复用**。

### 2.3 每集对账 → 能查出跨集漏项

`每集物料单` 不是形式：**逐集把"剧本里出现的 ID"与"索引表的 ☐"对一遍**，能查出
"某角色在某几集**没有对应资产**"这类**只在跨集视角下才看得见**的缺口。

> 📌 **实证**：本项目第一次填物料单时，就查出了「男主的家居戏**没有服装对应**」
> （原清单只有陪战夜/六年前西装/上班装三套）→ 补了 `CST_015` 并在三处同步。

## 四、落盘命名规范（速查 · 权威在骨架 README）

```
<主ID>_v<版本>_<角度或状态>.png
```

| 例子 | 含义 |
|---|---|
| `CHR_002_v1_front.png` | 角色 第 1 版 正面 |
| `CHR_001_State_9y_v2_turnaround.png` | 角色 九岁形态 第 2 版 三视图 |
| `CST_003_Wet_v1.png` | 服装 汗透状态 |
| `ENV_008_v1_angle04.png` | 场景 第 4 角度 |

> ⚠️ **三视图不靠画面上的文字**（`FRONT`/`SIDE`/`BACK` **禁入画面**，见 02 主控 §五）——
> 靠**文件名的角度后缀** + 拼板时的**位置**表达。

## 五、返工规范

| 情况 | 正确做法 | ❌ 错误做法 |
|---|---|---|
| 出图不满意（构图/光线） | 改提示词重出，文件名 `_v2` | 覆盖 `_v1`（丢可回溯性） |
| 角色脸不像 | 回角色索引**对锚点**，改提示词 | 直接换一张脸 = **重设计角色** |
| 场景各角度空间不对 | 回场景索引的**锁定项表**，逐条重写六项 | 每个角度各写一遍提示词 |
| 剧本要改（如加新角色） | **回 01** → 补 ID 登记 → 02 才动 | 02 自己编个 ID 直接用 |
| 资产不要了 | 标 `DEPRECATED`，**号位保留** | 删掉（旧引用指向空） |

## 六、每集"走完流程"的验收标准（每集都按这个验）

```
EP0X 完成 = 下面 7 条全打勾

[ ] S3 本集用到的 EXP_/POS_ 已建（主 ID ≥ DRAFT）
[ ] S4 本集 SHT_ 分镜表已出，每镜标了 ENV/CST/PRP

[ ] S6 本集 AUD_ 已提名并登记
[ ] 四张索引 + ID 注册表**已回填**
```

## 七、与工具 / 项目目录的关系（别重复劳动）

| 工具 | 管什么 | 什么时候用 |
|---|---|---|
| `python main.py gate <模块> <文件>` | 门禁预检 | 每个模块交付时 |
| `python main.py verify <ID>` | 核验产出实物（卡/提示词/图/索引表） | S2/S3 每批建完 |
| `python main.py drift` | 漂移检测（引用的 ID 在不在总表） | **每个模块交付时** |
| `python main.py angles <ENV_ID>` / `panorama` | 场景六角度 / 360° 基准 | S2 出场景 |
| `python 工具/校验.py` | 工作流自身的 12 类一致性 | 改完本目录后 |

**项目目录的约定**（具体某部剧放哪）：

```
<项目名>/
├── 00_PROJECT/
│   ├── 01_剧本/          01 的产物
│   ├── 02_资产索引/      02 的索引 + 视觉圣经
│   ├── 03_台账/          ID 注册表 + 未决项表
│   ├── 04_交付与出图/    交付包 + 生图提示词 + 出图流程
│   └── 05_流程/          本剧的物料单实例（规范指向本文件）
├── 01_WORLD/             世界观
└── 02_CHARACTERS/ … 10_CONSISTENCY/   ← 按 `02-服化道/项目骨架/` 建立
```

> ⚠️ 已知边界：`verify` / `drift` 扫的是 **07 运行时的资产库**，
> **默认不扫项目目录** —— 项目侧的对账**靠物料单末尾的回填清单手工做**。
> 要让机器校验项目目录，需先把资产导入 07 运行时（那是另一个决策，**不要默认做**）。
